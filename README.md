# 🐌 最强蜗牛插件

**astrbot_plugin_marvelous_snail** 是一个面向 AstrBot 的最强蜗牛攻略插件

[![GitHub](https://img.shields.io/badge/GitHub-Repository-blue?style=flat-square)](https://github.com/Himzandar/astrbot_plugin_marvelous_snail)

---

## ✨ 功能特性

- 🔍 搜索并关注公众号作者
- 📰 定时全量修正作者文章并自动推送最新内容
- 📚 本地缓存攻略并支持关键词检索与失效链接修正
- 🔐 自动解析文章中的密令
- 🤖 提供可被模型调用的 send_code 密令工具
- 📱 绑定游戏账号并执行签到
- 🌐 网页提交渠道服角色绑定与每日签到，支持 B站、华为、小米、OPPO、vivo 与荣耀
- ⏰ 每日自动签到，可配置礼包领取策略并向群聊或私聊推送汇总结果
- 🖼️ 攻略搜索结果、查询绑定与定时签到结果支持渲染为图片发送
- 🔄 每 30 分钟自动保活签到会话
- 🖥️ AstrBot 内嵌双服务管理页，维护签到绑定、攻略作者、文章缓存、推送目标与更新任务

## 📋 使用前准备

> ⚠️ 这个插件依赖外部服务和你自己抓取的请求头数据，不能开箱即用。使用前请先看完下面的准备步骤。

### 1. 自行部署 wechat-article-exporter

本插件不会帮你部署文章导出服务，你需要先准备一个可用的 wechat-article-exporter 接口。

- 项目地址：https://github.com/wechat-article/wechat-article-exporter
- 插件会调用这些接口：
  - GET /api/public/v1/account
  - GET /api/public/v1/article
  - GET /api/public/v1/download

### 2. 自行抓取微信签到 binds 请求头

推荐使用Reqable工具抓取

签到相关功能依赖你自己抓到的请求头，插件不会自动生成。

- 需要自行抓取最强蜗牛相关的 binds 请求头数据
- 将抓到的请求头以 Python 字典字符串形式填入 headers 配置项
- 请删除 `content-length` 字段，避免请求体变化后导致请求异常
- 如果没有正确配置 headers，以下功能都不可用：
  - 绑定账号
  - 手动签到
  - 自动签到
  - 定时签到汇总推送

### 3. 权限和使用场景说明

- 👮 作者管理相关命令大多要求管理员权限
- 💬 部分命令只允许私聊使用，代码里会直接拦截群聊、

## ⚙️ 配置说明

插件配置项与 `_conf_schema.json` 一致。

### 配置示例

```json
{
    "exporter_api_url": "http://127.0.0.1:3000",
    "exporter_auth_key": "your-auth-key",
    "headers": "{'user-agent': 'xxx', 'cookie': 'xxx'}"
}
```

### 配置项说明

| 配置项 | 必填 | 说明 |
| --- | --- | --- |
| exporter_api_url | 是 | wechat-article-exporter 的 API 地址，末尾不要带斜杠 |
| exporter_auth_key | 是 | wechat-article-exporter 的 auth key |
| headers | 否 | 你自行抓取的 binds 请求头，字典字符串格式 |

### 定时任务行为

- 📰 攻略更新任务：每 50 分钟自动执行一次
- 🔄 每次更新会对已关注作者做全量同步，自动删除 is_deleted=true 的文章，并刷新本地 synced_at
- 🐢 同步作者文章时，分页请求之间会随机等待 1 到 3 秒，避免请求过快导致失败
- 📝 自动签到任务：代码中固定为每天 08:10 执行
- 🔄 签到保活任务：代码中固定为每 30 分钟执行一次

## 🚀 快速上手

### 第一步：安装并启用插件

将插件放到 AstrBot 插件目录后，重启 AstrBot 或在插件管理中加载插件。

### 第二步：配置 exporter 和 headers

至少先配置以下两项，否则攻略相关能力无法正常工作：

- exporter_api_url
- exporter_auth_key

如果你还要使用签到功能，再额外配置：

- headers

### 第三步：搜索并关注作者

以下命令通常由管理员在私聊中操作：

```text
最强蜗牛 作者搜索
最强蜗牛 作者搜索 最强蜗牛 5
最强蜗牛 作者添加 1
最强蜗牛 作者列表
最强蜗牛 作者删除 最强蜗牛
```

说明：

- 作者搜索结果只保存在当前插件进程内存中
- 先执行 作者搜索，再执行 作者添加
- 作者搜索目前仅支持“最强蜗牛”

### 第四步：开启攻略推送

你可以在私聊或群聊里开启文章推送：

```text
最强蜗牛 攻略推送 开启
最强蜗牛 攻略推送 关闭
```

行为说明：

- 私聊场景下按发送者名称记录
- 群聊场景下按 group_id 记录
- 当已关注作者发布新文章时，插件会自动推送标题、简介和链接
- 如果作者名是“最强蜗牛”，插件还会尝试自动解析密令

### 第五步：拉取和搜索攻略

如果你想立即建立本地文章缓存，可以让管理员在私聊执行：

```text
最强蜗牛 获取文章 作者名
```

正常使用时，插件也会在定时更新时自动保存文章缓存。

缓存行为说明：

- 攻略缓存的修正和旧链接更新由定时任务统一处理
- 搜索攻略命令本身只检索本地缓存，不会在查询时临时刷新远端数据
- 已被删除的文章会在同步时自动从本地缓存移除

搜索攻略时使用：

```text
最强蜗牛 搜索攻略 关键词
```

交互流程：

1. 机器人先让你选择作者。
2. 你回复编号后，机器人返回渲染后的攻略结果图。
3. 如果结果文本超过 50 行，会自动拆成多张图片，并以聊天记录形式发送。
4. 你继续回复编号后，机器人会直接返回对应文章链接。
5. 每次等待用户输入的超时时间为 60 秒。

### 第六步：查询密令

插件会把解析成功的密令保存到本地文件，并提供 send_code LLM 工具用于发送当前有效密令。

如果你的 AstrBot 已开启模型工具调用，可以让模型调用：

```text
send_code
```

说明：

- 插件会把解析成功的密令保存到本地文件
- 过期超过约 2 个月的密令会被自动清理
- 当有效密令超过 50 条时，会按聊天记录形式分段发送

## 📱 签到功能用法

只有在正确配置 headers 后，下面这些命令才可用。

### 绑定账号

```text
绑定账号 13800138000
```

交互流程：

1. 机器人先发送个人信息处理告知。
2. 插件查询该手机号下的角色列表。
3. 你回复编号选择角色。
4. 绑定成功后会立即执行一次签到。
5. 手机号和角色 ID 会加密后写入本地文件。

### 渠道服绑定与签到

渠道服角色仅支持在网页门户提交，不在群聊内绑定。网页入口提供“官服账号 / 渠道服”切换，一次最多可提交 20 个渠道角色：

1. 选择渠道（B站、华为、小米、OPPO、vivo、荣耀）。
2. 填写角色 ID 与角色昵称。
3. 阅读并同意最新版个人信息处理告知后提交。

提交后本地服务器会立即拉取申请，执行渠道绑定并完成本次签到；网页会直接展示每个角色的成功、部分成功或失败结果。同一 QQ 重复提交已绑定角色时会标记“重复绑定”并显示角色昵称，仍会执行本次签到；跨 QQ 冲突会阻止静默转移。渠道绑定、签到与礼包请求共用已配置的 `headers`，但不收集手机号。每日全量任务会在周五额外查询并领取可领取礼包；手动“签到”和网页即时任务会按当前状态领取。

keep-sign 保活对渠道角色只执行绑定以维持会话，不重复签到。渠道角色按“渠道 + 角色 ID”去重；同一角色被其他 QQ 绑定时会阻止静默转移。绑定失败的角色会保留在网页暂存目录，直到原 30 分钟有效期结束，期间可再次发送“签到”或等待网页同步后重试。

### 查询和删除绑定

```text
查询绑定
注销绑定
```

说明：

- 查询绑定会以状态图形式展示当前用户的绑定数量、定时签到开关和各账号签到状态
- 注销绑定会进入选择流程，回复编号删除对应角色

### 手动签到

```text
签到
```

行为说明：

- 会对当前用户已绑定的所有角色逐个签到
- 插件会先刷新角色信息，再执行 binds 和 sign 请求
- 如果签到接口明确返回“很抱歉,已经领取过了”等提示，插件会显示“已领取”，不会误报为本次签到成功

### 定时签到推送

```text
定时签到推送 开启
定时签到推送 关闭
```

说明：

- 该命令只支持群聊，在目标群内执行即可登记或取消登记
- 开启后，每天自动签到完成后会向已登记群或私聊目标发送汇总
- 汇总默认先列出全部签到失败、数据异常、礼包失败与部分失败项，再为每个 QQ 保留一行签到与礼包概览
- 汇总图片会自动分页发送；渲染异常时降级为分页文本，不会形成超长单条消息
- 汇总图消息后会追加当天奖励图片

### 账号统计

```text
账号统计
```

这个命令会统计当前插件已保存的用户数和绑定账号数。

### 可视化管理页

插件内置 AstrBot 页面 `pages/manager/index.html`，启用插件后可在 AstrBot WebUI 的插件页面入口打开“最强蜗牛管理”。管理页顶部通过“签到服务 / 攻略服务”两个标签页独立展示两类功能。

签到服务提供：

- 用户、账号、角色、签到成功率与异常数量总览
- 用户列表搜索和状态筛选
- 单用户脱敏角色详情、签到状态与最近更新时间
- 新增官服角色绑定，编辑官服角色备注或身份信息，删除单个角色或整个 QQ 的全部绑定
- 展示渠道服角色、渠道名称、脱敏角色 ID 与最近一次签到结果；渠道角色只允许删除，绑定入口仍仅限网页
- 网页暂存申请、到期自动签到与过期数量
- 调度器、签到任务下次执行时间及签到配置是否就绪
- 手动同步网页申请
- 礼包领取类型切换（全部可领取 / 不自动领取）
- 定时签到汇总通知开关、奖励图片开关与汇总明细模式
- 新增、编辑和删除群聊或私聊通知目标

攻略服务提供：

- 已保存作者与仅剩本地缓存的作者列表
- 每位作者的文章数量、最近文章时间与缓存同步时间
- 新增、编辑或重命名作者，移除作者登记，单独清理本地文章缓存
- 攻略推送群聊/私聊目标及数量
- 新增、编辑和删除攻略推送目标
- 攻略 API 地址、认证密钥是否配置，以及攻略更新任务的下次执行时间
- 查看单个作者本地缓存的文章标题、摘要、发布时间与原文链接

攻略作者与推送目标可直接在管理页维护；攻略服务地址与认证密钥仍在 AstrBot 插件配置中设置。fakeid 不会回显，编辑作者时留空表示保持不变；重命名作者会同步迁移本地文章缓存。移除作者默认保留文章缓存，可再单独清理。攻略页不会返回 fakeid、exporter 密钥或签到密钥。

管理页支持完整的绑定维护：新增、编辑、删除单个角色，以及删除某个 QQ 的全部绑定。编辑时手机号与角色 ID 留空表示保持不变；修改身份后会将该角色重置为等待重新签到。删除操作不可撤销，且在全量签到或签到保活任务执行期间会被暂时锁定。

礼包领取策略统一作用于每日自动签到、手动签到与网页首次签到。即使未配置通知目标或关闭汇总通知，定时签到仍会正常执行。通知目标继续保存在 `push_datas/sign.json`，旧群聊配置无需迁移。

“汇总明细”支持三种模式：`issues_overview`（异常 + 用户概览，默认）、`issues_only`（仅异常）和 `full`（完整角色明细）。异常区会包含全部需要处理的账号及原因，用户概览按 QQ 展示签到成功数与礼包成功、部分失败、失败、无可领数量。汇总只渲染一次并复用于全部通知目标；图片或文本均安全分页，单个目标发送失败不会影响其他目标。旧配置缺少该字段时自动使用默认模式。

管理页仍只展示脱敏后的手机号与角色 ID，不返回请求头、同步令牌或加密密钥；新增和编辑提交的敏感字段会在写入磁盘前加密。

管理 API 同时提供签到服务与攻略服务的独立快照入口；旧聚合入口继续保留以兼容已有调用。攻略文章读取接口按作者名读取本地缓存，并对返回字段做长度限制与路径校验。

管理接口统一挂载在 `/astrbot_plugin_marvelous_snail` 下，并继承 AstrBot 登录鉴权：

```text
GET  /admin/signin/bootstrap
GET  /admin/strategy/bootstrap
GET  /admin/user?qq=<QQ>
GET  /admin/strategy/author/articles?name=<作者>&limit=<数量>
POST /admin/signin/sync
POST /admin/signin/gift/update
POST /admin/signin/notification/settings
POST /admin/signin/notification/add
POST /admin/signin/notification/update
POST /admin/signin/notification/delete
POST /admin/binding/add
POST /admin/binding/update
POST /admin/binding/delete
POST /admin/user/delete
POST /admin/strategy/author/add
POST /admin/strategy/author/update
POST /admin/strategy/author/delete
POST /admin/strategy/push/add
POST /admin/strategy/push/update
POST /admin/strategy/push/delete
```

`/admin/bootstrap` 与 `/admin/sync` 作为旧聚合入口继续保留。

## 💾 数据存储

插件会在 AstrBot 数据目录下生成以下数据：

```text
data/plugin_data/astrbot_plugin_marvelous_snail/
├── authors/
│   └── 作者名.json
├── codes/
│   ├── codes.json
│   └── code_error.json
├── push_datas/
│   ├── sign.json
│   └── strategy.json
├── settings/
│   └── signin.json
├── web_pending/
│   └── 用户ID.json
└── users/
    └── 用户ID.json
```

说明：

- **authors/作者名.json**：缓存作者文章列表，包含 synced_at、num、articles 等精简字段
- **codes/codes.json**：保存已解析的密令
- **codes/code_error.json**：记录解析失败的文章链接
- **push_datas/strategy.json**：保存攻略推送目标
- **push_datas/sign.json**：保存定时签到汇总推送的群聊或私聊目标
- **settings/signin.json**：保存礼包领取策略、通知开关、奖励图片开关与汇总明细模式
- **web_pending/用户ID.json**：网页绑定提交后的加密暂存队列
- **users/用户ID.json**：保存当前用户绑定的加密账号信息

## 🔒 隐私与安全

插件代码当前会对以下敏感信息进行加密存储：

- 手机号
- 角色 ID

派生后的 Fernet 实例会按密钥缓存，避免每次加解密重复执行 PBKDF2；密文格式与旧数据保持兼容。

内置管理页只返回脱敏后的手机号尾号和角色 ID，不返回请求头、同步令牌或加密密钥。管理写接口继承 AstrBot 登录鉴权，输入的手机号与角色 ID 会先加密再落盘。

但你仍然需要自行评估风险，特别是：

- 请求头由你自己抓取和保管
- exporter 服务由你自己部署和维护
- 任何接口失效、封禁或结构变更都可能导致插件失效

## 每日定时签到期间的绑定限制

每日 08:10 的全量签到启动后，插件会把“签到运行中”状态随网页同步心跳上报。此时：

- 插件内的 `绑定账号` 与 `批量绑定` 会直接提示暂不能绑定，可发送 `定时签到进度` 查看进度；
- 网页显示“每日定时签到执行中”的提示，并暂时禁用角色查询与绑定提交；
- 服务端同时校验状态，直接拦截绕过页面的角色查询、官服提交和渠道服提交；
- 全量签到结束后，插件在下一次心跳中自动恢复网页绑定，并在签到汇总中提示账号绑定已恢复。

该限制只影响新增绑定。已有角色仍会由每日任务正常签到；查询绑定、注销绑定与签到结果不受影响。

## 网页绑定与首次签到

从 `v1.6.0` 起，网页提交的数据会先加密保存在：

```text
data/plugin_data/astrbot_plugin_marvelous_snail/web_pending/
```

这些数据不会进入 `users/`，也不会被每日自动签到或保活任务提前执行。新版网页提交使用 `instant` 模式：插件每 5 秒检查一次，领取申请后立即处理本次新增角色，并通过 `POST /api/plugin/result` 回传按角色汇总的结果。网页随后轮询结果接口，直接展示成功、部分成功或失败原因。

旧版 `auto` 模式仍兼容，会按 `web_auto_sign_delay_seconds` 延迟执行；旧版 `manual` 记录仍可在 30 分钟内通过群内发送 `签到` 手动兜底。即时任务失败后不会无限重试，失败角色保留至原 30 分钟过期；用户仍可发送 `签到` 重试。处理流程会重新查询角色、完成首次绑定、签到和活动礼包领取，并继续执行跨 QQ 重复角色检查。网页支持一次提交多个最强蜗牛账号，Mac 端会按账号、服务器和角色共同去重；成功后角色才进入原有 `users/<QQ>.json` 并参与后续每日自动签到。

新增配置：

| 配置项 | 说明 |
| --- | --- |
| `web_portal_url` | 网页服务地址，例如 `https://xiyujing.com/snail` |
| `web_portal_sync_token` | 必须与门户 `SNAIL_PORTAL_SYNC_TOKEN` 完全一致 |
| `web_auto_sign_delay_seconds` | 仅用于兼容旧版 `auto` 模式；新版 `instant` 模式立即执行，默认 `300`，允许 `60～1500` |

`签到` 命令带有 60 秒用户冷却，不会触发全量用户签到。网页同步与即时任务每 5 秒检查一次；只有旧版 `auto` 模式会等待配置的延迟时间。

### 博客后台签到管理

从 `v1.6.5` 起，插件不再向云端上报本地绑定统计或签到日志。“蜗牛签到”后台改为直接展示绑定网站产生的操作审计，包括访问 IP、操作 QQ、角色查询与绑定提交结果；插件只保留网页绑定同步和签到所需的接口。

### 重复角色处理

插件启动时会自动清理跨 QQ 重复角色。保留顺序为：

1. 绑定账号数量更少的 QQ；
2. 角色总数更少的 QQ；
3. QQ 号字典序更小者。

单角色绑定、批量绑定和网页签到导入都会在写入前检查角色归属。若角色已被其他 QQ 绑定，会提示具体 QQ，不再重复绑定。
