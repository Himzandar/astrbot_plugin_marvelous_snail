# 🐌 最强蜗牛插件

astrbot_plugin_marvelous_snail 是一个面向 AstrBot 的最强蜗牛攻略插件，提供以下能力：

- 🔍 搜索并关注公众号作者
- 📰 定时全量修正作者文章并自动推送最新内容
- 📚 本地缓存攻略并支持关键词检索与失效链接修正
- 🔐 自动解析文章中的密令
- 🤖 提供可被模型调用的 send_code 密令工具
- 📱 绑定游戏账号并执行签到
- ⏰ 每日自动签到并向群聊推送汇总结果
- 🖼️ 攻略搜索结果、查询绑定与定时签到结果支持渲染为图片发送

这个插件依赖外部服务和你自己抓取的请求头数据，不能开箱即用。使用前请先看完下面的准备步骤。

## 🚧 使用前准备

### 1. 自行部署 wechat-article-exporter

本插件不会帮你部署文章导出服务，你需要先准备一个可用的 wechat-article-exporter 接口，并把地址和 auth key 填进插件配置。

- 项目地址：https://github.com/wechat-article/wechat-article-exporter
- 插件会调用这些接口：
  - GET /api/public/v1/account
  - GET /api/public/v1/article
  - GET /api/public/v1/download

### 2. 自行抓取微信签到 binds 请求头

签到相关功能依赖你自己抓到的请求头，插件不会自动生成。

- 需要自行抓取最强蜗牛相关的 binds 请求头数据
- 将抓到的请求头以 Python 字典字符串形式填入 headers 配置项
- 请删除 content-length 字段，避免请求体变化后导致请求异常
- 如果没有正确配置 headers，以下功能都不可用：
  - 绑定账号
  - 手动签到
  - 自动签到
  - 定时签到汇总推送

### 3. 权限和使用场景说明

- 👮 作者管理相关命令大多要求管理员权限
- 💬 部分命令只允许私聊使用，代码里会直接拦截群聊
- 🏷️ 作者搜索目前只支持关键词“最强蜗牛”

## ⚙️ 配置说明

插件配置项与 _conf_schema.json 一致。

### 配置示例

```json
{
  "exporter_api_url": "http://127.0.0.1:3000",
  "exporter_auth_key": "your-auth-key",
  "updata_cron": "0 5 * * *",
  "headers": "{'user-agent': 'xxx', 'cookie': 'xxx'}"
}
```

### 配置项说明

| 配置项 | 必填 | 说明 |
| --- | --- | --- |
| exporter_api_url | 是 | wechat-article-exporter 的 API 地址，末尾不要带 / |
| exporter_auth_key | 是 | wechat-article-exporter 的 auth key |
| updata_cron | 否 | 攻略自动更新周期，使用 5 段 Cron 表达式 |
| headers | 否 | 你自行抓取的 binds 请求头，字典字符串格式 |

### 定时任务行为

- 📰 攻略更新任务：由 updata_cron 控制
- 🔄 每次更新会对已关注作者做全量同步，自动删除 is_deleted=true 的文章，并刷新本地 synced_at
- 🐢 同步作者文章时，分页请求之间会随机等待 1 到 3 秒，避免请求过快导致失败
- 📝 自动签到任务：代码中固定为每天 08:10 执行
- 🔄 签到保活任务：代码中固定为每 30 分钟执行一次

## 🚀 快速上手

### 第一步：安装并启用插件

将插件放到 AstrBot 插件目录后，重启 AstrBot 或在插件管理中加载插件。

### 第二步：配置 exporter 和 headers

至少先配置以下两项，否则攻略相关能力无法正常工作：

- exporter_api_url
- exporter_auth_key

如果你还要使用签到功能，再额外配置：

- headers

### 第三步：搜索并关注作者

以下命令通常由管理员在私聊中操作：

```text
最强蜗牛 作者搜索
最强蜗牛 作者搜索 最强蜗牛 5
最强蜗牛 作者添加 1
最强蜗牛 作者列表
最强蜗牛 作者删除 最强蜗牛
```

说明：

- 作者搜索结果只保存在当前插件进程内存中
- 先执行 作者搜索，再执行 作者添加
- 作者搜索目前仅支持“最强蜗牛”

### 第四步：开启攻略推送

你可以在私聊或群聊里开启文章推送：

```text
最强蜗牛 攻略推送 开启
最强蜗牛 攻略推送 关闭
```

行为说明：

- 私聊场景下按发送者名称记录
- 群聊场景下按 group_id 记录
- 当已关注作者发布新文章时，插件会自动推送标题、简介和链接
- 如果作者名是“最强蜗牛”，插件还会尝试自动解析密令

### 第五步：拉取和搜索攻略

如果你想立即建立本地文章缓存，可以让管理员在私聊执行：

```text
最强蜗牛 获取文章 作者名
```

正常使用时，插件也会在定时更新时自动保存文章缓存。

缓存行为说明：

- 攻略缓存的修正和旧链接更新由定时任务统一处理
- 搜索攻略命令本身只检索本地缓存，不会在查询时临时刷新远端数据
- 已被删除的文章会在同步时自动从本地缓存移除

搜索攻略时使用：

```text
最强蜗牛 搜索攻略 关键词
```

交互流程：

1. 机器人先让你选择作者。
2. 你回复编号后，机器人返回渲染后的攻略结果图。
3. 如果结果文本超过 50 行，会自动拆成多张图片，并以聊天记录形式发送。
4. 你继续回复编号后，机器人会直接返回对应文章链接。
5. 每次等待用户输入的超时时间为 60 秒。

### 第六步：查询密令

插件会把解析成功的密令保存到本地文件，并提供 send_code LLM 工具用于发送当前有效密令。

如果你的 AstrBot 已开启模型工具调用，可以让模型调用：

```text
send_code
```

说明：

- 插件会把解析成功的密令保存到本地文件
- 过期超过约 2 个月的密令会被自动清理
- 当有效密令超过 50 条时，会按聊天记录形式分段发送

## 📱 签到功能用法

只有在正确配置 headers 后，下面这些命令才可用。

### 绑定账号

```text
绑定账号 13800138000
```

交互流程：

1. 机器人先发送个人信息处理告知。
2. 插件查询该手机号下的角色列表。
3. 你回复编号选择角色。
4. 绑定成功后会立即执行一次签到。
5. 手机号和角色 ID 会加密后写入本地文件。

### 查询和删除绑定

```text
查询绑定
注销绑定
```

说明：

- 查询绑定会以状态图形式展示当前用户的绑定数量、定时签到开关和各账号签到状态
- 注销绑定会进入选择流程，回复编号删除对应角色

### 手动签到

```text
签到
```

行为说明：

- 会对当前用户已绑定的所有角色逐个签到
- 插件会先刷新角色信息，再执行 binds 和 sign 请求
- 如果签到接口返回“很抱歉,已经领取过了”，插件同样会视作签到成功

### 定时签到推送

```text
定时签到推送 开启
定时签到推送 关闭
```

说明：

- 该命令只支持群聊，在目标群内执行即可登记或取消登记
- 开启后，每天自动签到完成后会向已登记群发送汇总图
- 汇总内容包含用户 ID 和该用户成功签到的账号数量
- 汇总图消息后会追加当天奖励图片

### 账号统计

```text
账号统计
```

这个命令会统计当前插件已保存的用户数和绑定账号数。

## 💾 数据存储

插件会在 AstrBot 数据目录下生成以下数据：

```text
data/plugin_data/astrbot_plugin_marvelous_snail/
├── 作者名.json
├── codes/
│   ├── codes.json
│   └── code_error.json
├── push_datas/
│   ├── sign.json
│   └── strategy.json
└── users/
    └── 用户ID.json
```

说明：

- 作者名.json：缓存作者文章列表，包含 synced_at、num、articles 等精简字段
- codes.json：保存已解析的密令
- code_error.json：记录解析失败的文章链接
- strategy.json：保存攻略推送目标
- sign.json：保存定时签到推送目标
- sign.json：保存已开启定时签到汇总推送的群聊目标
- users/用户ID.json：保存当前用户绑定的加密账号信息

## 🔒 隐私与安全

插件代码当前会对以下敏感信息进行加密存储：

- 手机号
- 角色 ID

但你仍然需要自行评估风险，特别是：

- 请求头由你自己抓取和保管
- exporter 服务由你自己部署和维护
- 任何接口失效、封禁或结构变更都可能导致插件失效

## 📌 已知限制

- 作者搜索目前只支持“最强蜗牛”
- 部分作者管理命令仅支持私聊且要求管理员权限
- 自动签到时间当前写死为每天 08:10，不走配置项
- 没有 exporter 服务时，攻略相关功能不可用
- 没有 headers 时，签到相关功能不可用
- send_code 依赖你的 AstrBot 已接入支持工具调用的模型或流程
